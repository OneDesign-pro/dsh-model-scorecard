# dsh-model-scorecard

**Русский** · [English](README.md)

Таблица оценок для каждой модели, настроенной в DeepSeek Harness. Для каждой
пары `(provider, model)` она отвечает на три отдельных вопроса: **насколько
быстро она работает**, **как часто она сбоит** и **отвечает ли она вообще прямо
сейчас**.

Смысл в том, чтобы заменить догадку измерением: **какую из настроенных моделей
использовать для этой задачи?**

Ответ собирается из трёх источников, которые держатся раздельно, а не
смешиваются в одно число:

- **История.** DeepSeek Harness уже пишет журнал каждой сессии — какой провайдер
  и какая модель дали какой ответ и когда. Плагин сворачивает эти журналы в
  цифры по моделям: время до первого токена, скорость декодирования, числа
  токенов, ошибки инструментов, повторы. Ничего не измеряется на лету — цифры
  воспроизводят то, что уже случилось, и плагин **не регистрирует ни одного
  хука** на пути запроса или потока.
- **Что заявляет адаптер.** Адаптер каждого провайдера умеет сказать, что за его
  модель: контекстное окно, применяемый по умолчанию потолок выходных токенов,
  принимаемые типы входа, режимы рассуждения. Это показано в **Подробнее** в
  панели.
- **Один живой запрос — и только когда об этом попросят.** Крошечный запрос
  через тот же маршрут `ctx.llm`, который берёт настоящий запрос, чтобы узнать,
  отвечает ли провайдер прямо сейчас. Ничего не опрашивается по таймеру.

Строка, которую гарантированно ни разу не запускали, всё равно строка: она несёт
«нет статистики», все остальные цифры не измерены, и есть круг статуса, который
делает её проверяемой. А модель, которой больше нет в конфигурации, спрятана за
переключателем **архив**, чтобы таблица никогда не рекомендовала то, что
запустить нельзя.

## Установка

```bash
dsh plugin --profile web add link:/path/to/dsh-model-scorecard
```

Или через менеджер плагинов, направив `install_bundle` на этот каталог. У плагина
нет рантайм-зависимостей и нет шага сборки.

**Переход с `dsh-model-stats`.** Имя здесь — зависимость, и установка идёт
через `link:`: pnpm разрешает её по ключу в `package.json` профиля и по `id:`
строки композиции в `cordis.patch.yml`, и оба ещё содержат старое имя, пока их
не изменят. Оставить любой из них — это не деградировавшая установка: плагина
просто нет, и страница Plugins показывает строку, под которой ничего нет.

```bash
# 1. the profile's dependency key and its bundle list
#    ~/.dsh/profiles/web/package.json
#      "dsh-model-stats":    "link:/path/to/dir"   ->  "dsh-model-scorecard": "link:/path/to/dir"
#      "dsh-model-stats",                          ->  "dsh-model-scorecard",     (dsh.profile.bundles)
# 2. the composition row — the id *is* the package name, there is no `name:` key
#    ~/.dsh/profiles/web/cordis.patch.yml
#      - id: model-stats                              ->  - id: model-scorecard
# 3. reconcile node_modules and restart
cd ~/.dsh/profiles/web && pnpm install
# restart DSH, and reload the browser tab completely — the panel's client bundle
# is served by the host, and the new routes only reach it after both are new.
```

Путь в ссылке не обязан совпадать с новым именем: pnpm ставит `link:` под тем
ключом, который дал профиль, и читает собственное `name` пакета из `package.json`
(проверено — `dsh-model-scorecard 0.3.0 <- …/dsh-model-stats`). Переименовать
каталог всё же стоит, но это отдельный шаг, а не условие установки. Больше ничем
руками ничего делать не нужно: каталог кэша переезжает сам, сохранённое
состояние панели читается из старого ключа, а старые маршруты продолжают
отвечать — см. *Переименование из `dsh-model-stats`* ниже.

## Где это найти

Три поверхности, один сборщик, поэтому они не могут разойтись:

1. **Панель** — Plugins → набор `dsh-model-scorecard` → его собственная страница.
   Сортируемая таблица всех настроенных моделей, где круг статуса и рейтинг стоят
   в первых трёх столбцах; нажмите на любой заголовок, чтобы отсортировать по
   нему, нажмите ещё раз — чтобы обратить порядок. Дерево над таблицей выбирает,
   о каких моделях таблица вообще, фильтр сужает её до некоторых провайдеров, а
   **Подробнее** под именем объясняет строку целиком.
2. **Инструмент `model_stats`** — те же числа обычным текстом, для агента.
3. **Инструмент `model_liveness`** — проверка доступности, со стороны агента.

`docs/panel.md` описывает панель целиком: каждый столбец, круг статуса, правило
выбора, архив и сохранённое состояние.

## Что он измеряет

Каждая цифра ниже свёрстана из записанной истории сессий одной точной пары
`(provider, model)`.

| Метрика | Значение |
|---|---|
| `rating` | технический рейтинг одной пары `(provider, model)`, 0–100: пропускная способность стриминга, медианный и p90 первого токена, причём вес измерения уменьшается вдвое каждые 30 дней от самого нового пригодного измерения пары. `~` = мало данных, `*` = самому новому пригодному измерению больше 30 дней — метки никогда не меняют число (см. *Рейтинг*) |
| `ttft` | время до первого токена: `step/start` → первый непустой фрагмент дельты. среднее / медиана / минимум / максимум / p90 |
| `ttft_clean` | та же медиана, но без времени, которое шаг потратил на неудачные попытки и бэкофф |
| `tps` | скорость декодирования в токенах/с: собственный счётчик выходных токенов провайдера за промежуток, в течение которого он их стримил |
| `e2e_tps` | те же токены за *всё* ожидание первого ответа — включая префилл. Именно по этой цифре следует выбирать модель |
| `prefill` | доля этого ожидания, потраченная до первого токена; по шагам, затем медиана |
| `overhead` | время в шаге, которое не является ни ожиданием первого токена, ни стримингом, — часть, за которую отвечает этот хост |
| `llm_mean` | полное время модели на шаг (`step/start` → `assistant/message`) |
| `cache%` | доля чтения из кэша в общем числе входных токенов |
| `out_tok` | суммарное число выходных токенов, о котором сообщил провайдер |
| `err` | неудачные результаты инструментов, отнесённые к модели, которая их вызвала |
| `err/100` | то же самое на 100 шагов — это доля, поэтому она измеряет качество, а не длину сессии |
| `err_model` | подмножество, вызванное собственным выводом модели: некорректный вызов инструмента или код, который не удалось выполнить |
| `interrupted` | шаги, перехваченные или отменённые на полпути |
| `retry%` | доля шагов, которым потребовался повтор, прежде чем они выдали ответ |
| `speed_conf` | доля стриминговых шагов, достаточно длинных, чтобы считаться надёжной скоростью |
| `maxContextTokens` (JSON) | наибольшая наблюдённая сумма входных токенов, чтения из кэша и записи в кэш на шаг; это не поддерживаемый моделью лимит контекстного окна. Отсутствующие данные об использовании сейчас дают ноль, поэтому ноль не доказывает наблюдённый пустой контекст |

`ttft` и `llm` в точности воспроизводят официальную свёртку `sessionStats` из
`@deepseek-ai/dsh-session-stats`. Проверено поле за полем против официального
модуля проекции на реальном журнале — совпадение до миллисекунды.

`docs/metrics.md` — это обоснование таблицы: как строится каждая цифра, какой
выбор мог быть сделан иначе и какое измерение его решило.

### Как читать цифры

- **`-` означает «не измерено», а не «ноль».** Модель, чей провайдер не сообщает
  число токенов, показывает `-`, а не `0`. Шаг, слишком короткий или слишком
  мелкий, чтобы считаться скоростью, исключается, а не додумывается.
- **Выбирайте модель по `e2e_tps`, а не по `tps`.** `tps` отвечает «насколько
  быстро она печатает»; `e2e_tps` — «насколько быстро я получаю токены». По всему
  корпусу медианная доля `prefill` равна **0.56** — больше половины ожидания
  первого ответа проходит до первого токена, и никакая скорость стриминга этого
  не показывает.
- **Счёт ошибок не является вердиктом.** `err` включает каждый неудачный вызов
  инструмента, в том числе ситуацию, когда harness нашёл файл изменённым под
  собой. `err_model` — это подмножество, которое действительно исправил бы другой
  выбор модели: на этой истории 282 из 783 ошибок. Наведите на ячейку, чтобы
  увидеть разбивку по кодам.
- **Читайте `retry%` вместе с `ttft_clean`.** Высокий `retry%` при высоком
  `ttft_clean` — это действительно медленная модель; высокий `retry%` при низком —
  ненадёжный маршрут. Пара разделяет «у провайдера плохой день» и «провайдер не
  может ответить».
- **`overhead` — единственная цифра про этот хост**, а не про провайдера. В
  сумме она невелика — около 2% времени модели — и это тот столбец, на который
  стоит смотреть, если медленным кажется сам harness, а не модель.
- **`maxContextTokens` — наблюдённое, а не заявленное.** То, что маршрут
  *заявляет* о своём контекстном окне, своём потолке вывода по умолчанию, своих
  типах входа и режимах рассуждения, — это отдельный источник, он показан в
  **Подробнее** в панели (см. [`docs/panel.md`](docs/panel.md)).
- **Измерения зависят от размера запроса, режима рассуждения и сети.** Отсутствие
  повторов не доказывает отсутствия сетевых задержек.

## Рейтинг

Все прочие столбцы — это отдельное показание, и взвешивать их оставлено читателю.
Рейтинг — единственная цифра, которая их взвешивает: одно число 0–100 для одной
точной пары `(provider, model)`, посчитанное только по зафиксированной истории — без
часов, без I/O, без импорта DSH — и опубликованное под версией (`technical-v1`),
так что более поздняя правка будет новой формулой, а не тихим дрейфом этой.

```
S = V50 / (V50 + 100)      generation throughput, half credit at 100 tok/s
L = 1 / (1 + T50 / 5000)   typical response,        half credit at 5 s
P = 1 / (1 + T90 / 15000)  slow response,           half credit at 15 s

score = 100 * S^0.45 * L^0.35 * P^0.20
```

Маршрут, стоящий сразу на всех трёх якорях, получает ровно 50, и оценка
монотонна: более быстрая выдача при неизменном остальном никогда её не снижает.

| Метка | Что означает | Влияние на число |
|---|---|---|
| `~` | предварительная: меньше 30 эффективных сэмплов или меньше 3 сессий | нет |
| `*` | самому новому пригодному измерению больше 30 дней | нет |
| `-` | оценки нет — одна из причин `no_samples`, `no_qualified_samples`, `insufficient_samples`, `pair_only` | н/д |

Для публикации нужно 10 пригодных **и** 10 эффективных сэмплов. Шаг, чей
интервал слишком короткий, слишком мелкий или слишком фрагментированный, чтобы
считаться скоростью, вносит вклад во все три множителя или ни в один из них,
так что множители всегда описывают одни и те же шаги.

**Чем рейтинг не является.** Не интеллектом, не правильностью, не качеством
ответов, не ценой, не ёмкостью контекста, не текущей доступностью. Неудачная
проба доступности намеренно не является входом: маршрут, к которому нельзя
достучаться прямо сейчас, сохраняет оценку, которую заработала его история, а
колонка статуса отвечает на вопрос «прямо сейчас».

`docs/rating.md` содержит полную политику: якоря, веса по свежести, популяцию и
то, что двигает оценку, а что нет.

## Отвечает ли модель *прямо сейчас*

История отвечает на вопрос о том, как модель себя вела. Она не может ответить,
работает ли провайдер в эту минуту, а это и решает, что запускать дальше. Именно
это и есть колонка **статус**: одна проба на модель, запускаемая по вашему
запросу.

Проба — это наименьший возможный вызов, отправленный **через `ctx.llm`**: тот
же маршрут, протокол, учётные данные, адаптер и форма запроса, что у настоящего
запроса, и ни одного собственного параметра. Форма, которую отправляет только
этот плагин, измеряла бы только этот плагин; зелёный круг означает, что до
модели дошёл сам harness.

| Круг | Значение |
|---|---|
| зелёный | модель ответила |
| серый | пробы не было |
| пульсирующий (акцент) | проба этой модели идёт прямо сейчас |
| янтарный | провайдер отказал по лимиту — лимит исчерпан (*лимит исчерпан*) или аккаунт притормаживают (*слишком часто*) |
| сплошной красный | проверка не удалась и отвечать было некому: таймаут, оборванное соединение, ошибка провайдера. Ячейка печатает собственный статус сбоя, когда у панели нет для него слова — *timeout*, *server*, *http_500*, *transport* |
| залитый красный квадрат | строка не настроена, и исправление на этой стороне: *нет доступа* (ключ отвергли или он отсутствует), *нет маршрута* (для провайдера не объявлен эндпоинт), *нет модели* (провайдер не знает эту модель) |

Тон делится по тому, **чей это ход**: янтарный — это аккаунт (пауза или
пополнение), залитый квадрат — наша сторона (ключ, эндпоинт, список моделей),
сплошной красный — их (подождать или обойти). Модель, ответившая в истории
*после* неудачной проверки, рисуется зелёной и помечается *по истории* — сбой
старше доказательства.

| Где | Что она проверяет |
|---|---|
| круг в строке | эту одну модель |
| **Проверить все** | каждую настроенную модель, перепроверяя даже свежий ответ |
| **Проверить выбранные** | модели, отмеченные в дереве «Модели», перепроверяя даже свежий ответ |
| строка провайдера в виде провайдеров | модели этого провайдера |

Проверка сотни моделей — это не один HTTP-запрос: хост сразу отвечает на `POST`,
продолжает проверять в фоне по четыре за раз, а панель следит за `pending` до
нуля через обычный `GET`. Результаты записываются в `liveness.json` рядом со
снимком свёртки и переживают перезапуск.

```js
model_liveness()                            // every model with no fresh answer
model_liveness({ provider: 'openrouter' })  // one provider's models
model_liveness({ model: 'gemini-3.8-flash', provider: 'openrouter' })  // exactly one
model_liveness({ all: true })               // re-probe everything
```

```
status provider           model                        ms      source
OK     nvidia1            z-ai/glm-5.3-flash           130863  llm
OK     openrouter         google/gemini-3.8-flash      1501    llm
FAIL   openrouter         google/gemma-4-31b-it:free   526     llm  RATE_LIMIT 429: Rate limit exceeded: free-models-per-day
```

В `docs/panel.md` классификация разобрана целиком: как код становится состоянием,
как читается собственное предложение провайдера и как сортируется колонка
статуса.

## HTTP API

Два маршрута для любого клиента, кроме панели. `GET` — тот, что был раньше, и он
отвечает ровно как раньше:

```
GET /api/model-scorecard?sort=&dir=&view=&provider=&archived=&limit=
```

`dir` — это `asc` или `desc`, `provider` — список через запятую, его можно и
повторять, `archived=1` просит архив, а `limit` ограничивает страницу 200
строками. Всё остальное, включая отсутствие параметров, — это умолчание: архив
скрыт, страница на 50 строк.

`POST /api/model-scorecard/query` — тот, что принимает выбор. Тело запроса —
объект JSON:

```json
{
  "sort": "ttft", "dir": "asc", "view": "model", "limit": 200, "archived": false,
  "selection": {
    "live":    { "base": "measured", "providers": { "codex": "all" }, "pairs": { "codex\u0000gpt-6-mini": "off" } },
    "archive": { "base": "none", "providers": {}, "pairs": {} }
  }
}
```

`selection` — это `null` для «никакой политики вовсе» (вопрос, на который
отвечает `GET`), а во всех остальных случаях документ правил. Тело, которое не
является объектом JSON, неизвестный `sort`, `dir` вне `asc`/`desc`, `limit` вне
1–2000, небулево `archived`, испорченный выбор, тело больше мегабайта или метод
не `POST` **отклоняются с 400/405/413**, а не получают ответ на другой вопрос:
хост, наполовину прочитавший выбор, отвечает на вопрос, который никто не задавал.

### Выбор — это правило, а не список

Таблица панели — про те модели, которые вы выбрали, и выбор — это **правило**.
Разница видна на следующее утро: под «всё от этого провайдера» модель, которую
конфигурация заночевала, появится в следующем ответе, а список имён, снятый
вчера, её не назовёт.

У правила две области, `live` и `archive`, и у каждой три уровня:

| Уровень | Что говорит |
|---|---|
| `base` | `measured` (каждая модель с историей), `all` или `none` |
| `providers[name]` | `all`, `measured` или `none` для одного провайдера |
| `pairs["provider\u0000model"]` | `on` или `off` для одной модели — исключение, которое перебивает оба |

Предшество ровно такое, сверху вниз: сначала явная пара, потом правило
провайдера, потом база области. Первое открытие использует
`{ live: { base: 'measured' }, archive: { base: 'none' } }` — каждая модель с
историей и ни одной выведенной из обращения.

Четыре поля ответа существуют ради выбора:

| Поле | Что это |
|---|---|
| `selection` | применённый документ правил в каноническом виде — `null`, когда вопрос не нёс никакого |
| `catalog` | каждая модель в области с `{ model, archived, noStats, steps }` — для дерева |
| `coverage` | по провайдерам, `{ selected, total }` — отсюда читается «N из M моделей» |
| `truncated` | `true`, когда выбор больше страницы: таблица — не весь ответ |

Оба маршрута принимают любой ключ столбца таблицы (`rating`, `steps`, `ttft`,
`speed`, `errors`, `lastSeen`, `name`, `ttftP90`, `tpsMax`, `confidence`, `llm`,
`cache`, `retry`, `ttftClean`, `e2e`, `prefill`, `overhead`, `errorRate`,
`modelErrors`, `interrupted`, `liveness`), а агентский инструмент `model_stats`
использует свой отобранный перечень из шести порядков — пять, которые были
всегда, плюс `rating`, и по умолчанию по-прежнему `steps`. Неизвестный порядок
падает на `steps`, а не ломает запрос, и ответ повторяет тот порядок, который
действительно применил.

### Фильтр по провайдеру

Обе поверхности могут отвечать про некоторых провайдеров вместо всех. Имена
точные, и сразу несколько: `?provider=openrouter,codex` в URL и та же строка
(или массив JSON) в параметре `provider` инструмента. Фильтр, который не совпал
ни с чем, — это вопрос с ответом, а не повод вернуть всю таблицу: текстовый
отчёт называет запрошенные имена, а ответ сохраняет каждого провайдера, которого
знает отчёт.

## Конфигурация

`cordis.patch.yml` вставляет одну строку:

```yaml
- insert:
    - id: model-scorecard
      name: dsh-model-scorecard
      config: {}
```

Свёрнутый снимок и каждый результат пробы лежат в
`~/.dsh/cache/dsh-model-scorecard/` — это `fold-snapshot.json` и `liveness.json`.
Расположение переопределяется переменной `DSH_MODEL_SCORE_CARD_CACHE_DIR`. Снимок
хранит только свёрнутые сэмплы, никогда не события, и заменяется атомарно.

Заголовок, описание и тексты панели приходят из `locale/ru.json` и
`locale/en.json`, а иконка — из `icon.svg`. Панель следует за языковыми
настройками самого GUI.

## Нагрузка на Harness

**Этот плагин не регистрирует ни одного хука на пути LLM-запроса или потока.**
Он только читает историю: один раз в фоне после активации и затем по запросу.

Открытие панели обслуживается в три фазы, от дешёвой к дорогой — свёртка в
памяти, затем снимок на диске, затем ограниченный проход только по изменившимся
сессиям, — поэтому таблица никогда не ждёт холодной свёртки. **Каждый запрос
ограничен**: маршрут панели 2.5 с, инструмент 20 с, и каждый возвращает то, что
уже свёрнуто, плюс счётчик `pending`.

На реальном хранилище (483 сессии / 34 586 шагов) свежий процесс отвечает на
весь корпус за **0.70 с с одним прочитанным журналом** против 33.2 с холодного
прохода без снимка.

В `docs/load-and-cache.md` — цепочка фаз, контракт снимка и бюджет на стороне
браузера целиком.

## Переименование из `dsh-model-stats` (2026-10-01)

Плагин отвечал числами на один вопрос, а теперь отвечает на три, поэтому имя
называет то, что содержит строка. `docs/migration.md` объясняет переименование;
читателю нужна вот эта таблица:

| | было | теперь | при обновлении |
|---|---|---|---|
| пакет | `dsh-model-stats` | `dsh-model-scorecard` | по нему ключуются зависимость профиля и строка композиции — см. *Установка* |
| маршруты | `/api/model-stats…` | `/api/model-scorecard…` | четыре старых ещё отвечают один релиз, из тех же объектов-обработчиков |
| кэш | `~/.dsh/cache/dsh-model-stats/` | `~/.dsh/cache/dsh-model-scorecard/` | перемещается через `rename` при первой активации: свёрнутый снимок и каждый сохранённый результат пробы едут с ним, и журнал активации говорит, в какую сторону это пошло |
| переменная окружения | `DSH_MODEL_STATS_CACHE_DIR` | `DSH_MODEL_SCORE_CARD_CACHE_DIR` | старое имя всё ещё перенаправляет кэш; новое побеждает, когда заданы оба |
| состояние панели | `dsh-model-stats:prefs:…` | `dsh-model-scorecard:prefs:…` | читается один раз из старых ключей и пишется под новым; старые ключи остаются на месте |

Имена инструментов `model_stats` и `model_liveness` **не** менялись: они глобальны
для DSH, не зависят от имени пакета, и их переименование изменило бы путь запроса
каждой сессии, которая не просила себе миграции.

## Использование инструмента `model_stats`

Регистрируется глобально, поэтому доступен в каждой сессии:

```
model_stats(sort: "ttft")            # fastest median first token
model_stats(sort: "speed")           # fastest median decode
model_stats(sort: "errors")          # least stable first
model_stats(sort: "rating")          # the 0-100 technical rating, best first
model_stats(view: "provider")        # one row per provider, all its models folded together
model_stats(provider: "openrouter,codex")   # these providers only
model_stats(provider: ["openrouter"], sinceMs: <epoch-ms>)
model_stats(archived: true)          # plus the models the configuration no longer serves
```

Вывод — таблица обычным текстом плюс строки сводки, называющие самый быстрый
первый токен, самое быстрое декодирование и каждую модель, которая дала ошибки.
Каждая строка-победитель печатает, по чему решала: `fastest first token: … (46
ms) — over 28 sample(s)`, и выбирает победителя только среди строк с не менее чем
20 сэмплами собственной цифры этой строки.
